- **Original per-circle Firestore GCP project IDs** (historical-data verification/future imports): Vancouver = `vancouver-cbc-registration`, Nanaimo = `nanaimo-cbc`, Ladner = `ladner-cbc`, Comox Spring = `comox-spring`. `gcloud auth login` + `gcloud auth application-default login` needed locally first (session tokens expire).
- **Constructing a valid Flask session cookie without a real login** (used by the test suite's `login_as_test_user()`, also handy for manual debugging): `flask.sessions.SecureCookieSessionInterface().get_signing_serializer(app).dumps({'user_email': ..., 'user_name': ..., '_permanent': True})` — works because there's no Flask-Session installed (session data is a plain signed cookie) and every local process shares `SECRET_KEY` via `.env`. **Never set an explicit cookie `domain` when injecting this into Selenium** — even one matching the current host exactly forces a leading-dot-domain cookie distinct from Flask's own host-only cookie, and the browser then sends both, silently breaking auth. Delete any pre-existing `session` cookie first.
- **Local dev**: `python app.py` now works fine directly (confirmed no circular-import issue this session — the previous PROMPT.md's claim that this requires `flask run` instead was stale/no longer reproduces). Needs `.env` with `DATABASE_URL`, `TEST_MODE=true`, `SESSION_COOKIE_SECURE=false`.
- **This is a multi-circle platform with no default/fallback circle.** Local dev/testing requires a real resolvable circle hostname: add `127.0.0.1 test.cbc.test` to your hosts file and browse `http://test.cbc.test:8080`, not raw `localhost`/`127.0.0.1`. The dedicated `test` circle's 25 areas are a copy of Vancouver's, translated 45km **northeast** (not northwest — that would overlap the real Sechelt circle) via `utils/Test_CBC_Areas.kml` (untracked, already created and imported by the user this session).
- **The test suite has a structural production-safety guard** (`tests/conftest.py`'s `pytest_sessionstart`) that hard-aborts the whole run unless `DATABASE_URL`'s host and the resolved test target are both `localhost`/`127.0.0.1`/`.test`-suffixed. There is no override — if you need a remote target, that's a deliberate decision outside this guard's scope, not a flag to flip.
- **`pytest.ini` must use `[pytest]` as its section header**, not `[tool:pytest]` (that header is for `setup.cfg`/`tox.ini` only) — and multi-line ini values (`addopts`, etc.) must never have trailing inline `#` comments, which get included as literal text and corrupt the option silently.
- **Testing authenticated routes via `app.test_client()`**: pass `headers={'Host': ...}` to `session_transaction()` itself, matching whatever host the real request will use.
- **`certbot` must run in WSL**, never native Windows, always `--key-type rsa`. Full procedure: `docs/TLS_CERT_RENEWAL.md`.
- **Windows `.venv/Scripts/python.exe` doesn't understand Git Bash's `/tmp` path translation** — use a real Windows path (e.g. the scratchpad directory) when a script run via the Windows python.exe needs to read/write a file also referenced from Bash.
- **This repo's venv is at `.venv/`** (not a bare `venv`) — use `.venv/Scripts/python.exe -m pytest ...` from Git Bash if a bare `pytest`/`python` resolves to the wrong interpreter (there are multiple Pythons on this machine's PATH).
